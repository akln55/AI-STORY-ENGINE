# Dialogue System

## Authority

Dialogue is a hybrid system:

- The engine owns whether an NPC can be reached.
- Scenario data owns canonical speech/personality/knowledge constraints.
- Runtime NPC state owns current location, alive state, disposition, personality, goals and relationships.
- The AI produces dialogue and may propose state changes.
- Validation decides whether proposed changes are legal.

The AI cannot bypass encounter conditions by claiming that a conversation occurred.

## Flow

```text
player: talk to <npc>
        |
        v
resolve stable id / display name
        |
        v
EncounterResolver
        |
   blocked? ---- yes ---> no AI call
        |
       no
        v
assemble normal context
        +
dialogue target context
        |
        v
AI structured response
        |
        v
validation gate
        |
        +--> relationship/NPC effects
        +--> memory updates
        +--> scenario events
        |
        v
quest evaluation with talked_to=<npc>
```

## Canonical character dialogue data

A character record may contain:

- `speech_style`
- `dialogue_rules`
- `knowledge_boundary`
- personality/traits/goals/preferences
- relationship and presence data

These are context constraints. They do not directly mutate runtime state.

## Quest integration

A `talk` objective is completed from the authoritative `talk to <npc>` action after the target has passed encounter validation. The AI's prose is never inspected to determine whether the objective completed.

## v1.16 integration

Dialogue now supports relationship flags through the structured effect contract.
A conversation with NPC A cannot mutate NPC B through `npc_changes`; unrelated NPC
changes are discarded before validation. Dialogue may still trigger existing
scenario events and validated relationship consequences.

Available actions returned by the AI are surfaced as player-facing suggestions only;
they are not authoritative commands.

## Future extensions

The following remain separate systems and should not be smuggled into the dialogue layer:

- branching dialogue trees
- dialogue choices with scenario-defined conditions
- promises/deals/quests generated by conversation beyond validated effects
- faction reputation consequences
- NPC autonomous conversations
- long-term dialogue topic memory
